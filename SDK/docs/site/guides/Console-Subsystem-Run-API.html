Console subsystem Run API

Kath 0.31.0 introduces the first beginner-facing unified subsystem lifecycle API. The Console subsystem selects a complete console policy with one call while preserving KernelConsole as the professional low-level API.

Basic use

using Inu.Kernel.Console;

Console.Run(ConsoleType.Auto);
Console.WriteLine("Inu is running.");

Console modes

  • Auto resolves to framebuffer text when GOP is available, otherwise serial.
  • TextAscii uses ASCII framebuffer text with the serial debug mirror.
  • TextAnsi preserves ANSI bytes on serial and interprets the supported framebuffer control subset.
  • FramebufferText uses the GOP framebuffer text renderer with serial mirroring.
  • Graphics leaves the framebuffer to the graphics subsystem while keeping serial/debug output.
  • Serial uses only the primary serial/debug transport.

Lifecycle

Console.Run(ConsoleType.TextAnsi);
Console.Stop();
Console.Resume();
Console.Unload();

Stop() retains the configured console and framebuffer history for a fast Resume(). Unload() tears down the logical binding; a later Run(...) can initialize it again using the retained boot context.

State

ConsoleState state = Console.State;
ConsoleType active = Console.Mode;
ConsoleType requested = Console.RequestedMode;
bool running = Console.IsRunning;

Professional layer

The high-level Console class configures the existing KernelConsole, framebuffer, serial, font, buffering and input implementation. Professional code can continue using KernelConsole directly for exact buffer, font, diagnostic, caret, input and raw-output control.

The same lifecycle vocabulary is intended for later subsystem APIs: Run(mode), Stop(), Resume() and Unload().
